# Implementation brief for ADR 0055 (replanning wired into serve)

Two parts. Every design decision is in ADR 0055; read it first, then AGENTS.md, ADR 0042 and ADR 0040. Do not revisit the decisions; if one turns out wrong, stop and report the evidence. No box runs.

All parts: failing tests first, then code. Every local cargo command goes through the shared lock with one job: `L=/c/Users/pierr/AppData/Local/Temp/claude/cargo-host.lock; until mkdir "$L" 2>/dev/null; do sleep 20; done; CARGO_BUILD_JOBS=1 cargo <args>; rmdir "$L"`. Prefer `cargo test -p <crate>` while iterating; CI on the pushed `track-*` branch is the compile loop when the lock starves. At most one `gh` call per 15 minutes. Done means `cargo build --workspace`, `cargo test --workspace`, `cargo clippy --workspace -- -D warnings`, `cargo fmt --check` pass on Windows and Linux (Rule 11), `python -m pytest tests/test_alert_rules.py` passes, and ADR 0055 gets an "Implementation notes" section. Commit only if your brief says so.

## Part A

**Goal.** `tetraeder serve --plan auto|<file>` picks or loads a plan, lowers it to the engine's load options, serves it, records the prediction and the residual, and lets the ADR 0042 replanner drain, re-plan and restart on drift (in-process) and on SLO burn, load shift or device change (admin route). Without `--plan`, `serve` behaves exactly as today.

**Read first.** ADR 0055, 0042, 0040, 0046; `crates/control/src/replan.rs`; `crates/planner/src/{candidate.rs,builder.rs,lower.rs,score.rs,whatif.rs,layout.rs,diff.rs}`; `crates/costmodel/src/predict.rs` (module doc: breakdown labels); `crates/profiler/src/{discover.rs,graph.rs}`; `crates/tetraeder/src/{serve.rs,plan.rs,engine_args.rs}`; `crates/scheduler/src/{scheduler.rs,load.rs}` (read only); `crates/telemetry/src/{ring.rs,setup.rs,metrics.rs}`; `crates/gateway/src/server.rs`; `deploy/alerts/slo.yml`; the "Planner and detector" row of `deploy/grafana/dashboards/overview.json`.

### A1. Planner: CPU placement, recognize, project, lower (crates/planner)

- `candidate.rs`: new variant `Placement::Cpu` (serde tag `cpu`): every unit on `cpu0`, no GPU device in the stage. Update `describe` (`"cpu"`), `gpu_share` (0), `build_plan` (all units including experts and head on `CPU`, stage devices `[CPU]`, KV all host, no workspace), `footprint` (everything host). `score::features` treats it like `None` (all on the CPU, op offload false). `to_variant_args` renders `-ngl 0`. Check every `match` the compiler flags (campaign.rs too); `Cpu` never appears in `enumerate`/`enumerate_builder` output, so committed candidate sets and their CI tests are unchanged.
- `candidate.rs`: `pub fn enumerate_cpu(budget: &Budget, layout: &ModelLayout, w: &Workload) -> Enumeration`: placement `Cpu` times `thread_values(budget.threads)` times `UBATCHES`, op offload `false`, dropped when the footprint exceeds `budget.ram_bytes`; ids `c00`... in that order.
- `lower.rs`:
  - `pub fn recognize(plan: &Plan, layout: &ModelLayout) -> Result<(Placement, Knobs), String>`: inverse of `build_plan` for `Dense`, `Moe`, `Builder`, `Cpu` (read the assign rules' spans and devices and the stage's `expert_cache`). One replica, one stage, `layers == Span(0, L)`, formats equal to `layout.main_format()`, no `kv_format` other than default, empty `role_formats`; anything else is `Err` naming what is not executable (`"two replicas"`, `"kv format q8_0"`, ...).
  - `pub struct Applies { pub llama_op_offload: bool, pub builder_ubatch: bool }` with `Applies::today()` = both `false` and `Applies::all()` = both `true`. `pub fn project(&self, plan: &Plan, engine: ServeEngine) -> (Plan, Vec<String>)`: when `!llama_op_offload` and the engine is libllama, sets `knobs.op_offload = Some(true)`; when `!builder_ubatch` and the engine is the builder, sets `knobs.ubatch = Some(512)` (`tetraeder_scheduler::MOE_CHUNK`; keep a planner constant `SERVE_BUILDER_UBATCH = 512` with a comment naming it). Returns the changed knobs as messages. `pub enum ServeEngine { Llama, Builder }`.
  - `pub enum Lowered { Llama { n_gpu_layers: i32, cpu_patterns: Vec<String>, threads: u32, batch: u32, ubatch: u32, op_offload: bool }, Builder { gpu: Option<u32>, expert_slots: Option<u32>, ram_slots: Option<u32>, threads: u32, ubatch: u32, op_offload: bool } }` and `pub fn lower(plan: &Plan, layout: &ModelLayout, engine: ServeEngine) -> Result<Lowered, String>` via `recognize`. Llama: `Dense` -> `dense_ngl`, `Moe` -> `-ngl 99` plus `cpu_experts_pattern` (as a `<regex>=CPU` string), `Cpu` -> `0`; `batch = max(2048, ubatch)`. Builder: `Builder` -> `gpu: Some(0)` (`gpu0` -> index 0), `expert_slots = None` when `vram_slots >= n_expert` else `Some`, `ram_slots = Some(r)` when `r > 0`; `Cpu` -> `gpu: None`, all experts resident; `Dense`/`Moe` with `ServeEngine::Builder` -> `Err`. `Builder` with `ServeEngine::Llama` -> `Err`.
  - Rewrite `to_variant_args` to render `Lowered::Llama` (same output: the existing `moe_args` and dense tests must pass unchanged).
- `whatif.rs` (or a new `fill.rs`): `pub fn fill_from_priors(hw: &mut HardwareGraph, priors: &Priors) -> Vec<String>`: for each GPU without `compute` or `bandwidth_bytes_per_s`, take them from `priors.gpu_class` matched by device name (`Source::Prior`); returns notes for devices it could not fill. CPUs are not filled.
- New `crates/planner/src/serve.rs` (pure, no I/O), re-exported from `lib.rs`:
  - `pub struct ServeInput { pub hw: HardwareGraph, pub layout: ModelLayout, pub budget: Budget, pub ctx: u32, pub workload: Workload, pub engine: ServeEngine, pub applies: Applies }`.
  - `pub fn budget_of(hw: &HardwareGraph, quota: u32, vram: Option<u64>, ram: Option<u64>) -> Budget`: `gpu0` capacity (0 without a GPU), `cpu0` capacity, threads `min(cpu0.threads, quota)`; overrides win.
  - `pub struct Picked { pub plan: Plan, pub placement: Placement, pub prediction: Option<Prediction>, pub notes: Vec<String> }`.
  - `pub fn candidates(inp: &ServeInput) -> Vec<Plan>`: the enumerator by engine and GPU presence (`enumerate`, `enumerate_builder`, `enumerate_cpu`), sized with `Workload { prompt: ctx - workload.gen, gen: workload.gen }`, each plan projected with `applies`, deduplicated in order, and dropped if the projected footprint no longer fits.
  - `pub fn predict_plan(hw: &HardwareGraph, layout: &ModelLayout, plan: &Plan, w: &Workload) -> Result<Prediction, String>`: `recognize`, then `score::features` (llama placements and `Cpu`) or `score::builder_features` with hit `vram_slots / n_expert` (uniform routing prior), then `costmodel::predict`.
  - `pub fn pick(inp: &ServeInput) -> Result<Picked, String>`: lowest `request_s`; ties by enumeration order; when any prediction fails, the first candidate with `prediction: None` and a note. `Err` only when there is no candidate.
  - `pub fn correct_for_drift(hw: &HardwareGraph, pred: &Prediction, measured_step_s: f64) -> Option<HardwareGraph>`: take `pred.binding`; the device is the text after `:` (`compute:cpu0`, `offload_copy:cpu0`, `offload_compute:gpu0`); `switches` or unknown -> `None`. With `t = 1 / tg_tok_s` and `t_b` the binding term of `tg_breakdown`, `k = (measured - (t - t_b)) / t_b`, clamped to `[0.1, 10]`; divide that device's `compute.flops_per_s`, `bandwidth_bytes_per_s.value` and every `thread_curve` point's rates by `k` (mark `Source::Measured`).
  - `pub struct Proposed { pub plan: Plan, pub prediction: Prediction, pub gain: f64 }` and `pub fn propose(inp: &ServeInput, current: &Plan) -> Option<Proposed>`: `pick`; `None` if the pick equals `current`, has no prediction, or current's prediction fails for a reason other than not fitting; `gain = 1 - t_new / t_cur` with `t = request_s` for `inp.workload`, and `gain = 1` when `current` no longer fits: its footprint exceeds `inp.budget`, its `knobs.threads` exceed `budget.threads`, or it uses a GPU the graph no longer has. `None` when `gain <= 0`.
  - `pub fn regret(inp: &ServeInput, current: &Plan) -> Option<f64>`: current's predicted `request_s` over the pick's, minus 1.

Make `layout::fixtures` `pub` behind `#[cfg(any(test, feature = "fixtures"))]` or `#[doc(hidden)] pub` so the integration test can use it.
3. `crates/planner/tests/serve_replan_sim.rs` (Rule 4, simulated fixtures and faults): graphs = every `crates/costmodel/fixtures/*.toml` with `cpu0` (plus a CPU-only copy with the GPUs removed), `planner/fixtures/rtx3090_prior.toml`, and a new `planner/fixtures/cpu_only.toml` (one `cpu0`, 8 threads, compute and bandwidth set); layouts `fixtures::moe()` and `fixtures::dense()`; engines `Llama` and, for the MoE layout, `Builder`. Per combination take `current = pick(...)` then:
   - no fault: `propose` with the same input is `None`; `correct_for_drift` with the measured step equal to the prediction leaves the next pick unchanged.
   - CPU co-tenant (truth = `cpu0` rates halved) and GPU throttle (truth = `gpu0` rates halved): measured = truth's decode step for `current`; corrected = `correct_for_drift(belief, pred, measured)`; `propose` on the corrected graph: any proposal lowers, fits the budget, and when the fault is on the binding device its truth `request_s` is at most current's truth `request_s`. For the CPU fault the proposal's `gpu_share()` is at least current's.
   - VRAM shrink (budget `gpu_bytes` to 60%): when `current` no longer fits, `propose` returns `Some` with `gain == 1` and a fitting plan; when it still fits, behaviour as no fault.
   - Determinism: two runs give identical picks and proposals.
   - `fill_from_priors`: a discovered-style graph (GPU named `NVIDIA GeForce RTX 3090`, no compute) gets the prior's numbers.
