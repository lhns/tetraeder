# 0040. Planner: executable candidates, a cost model calibrated from anchor runs, scored by regret and rank

Status: Proposed (Phase 3a)

## Context

Phase 3a delivers the planner (docs/plan.md "Planner and optimizer"): search, hints, explain, diff, what-if, and an exit test of regret at most 10% and Spearman rank correlation at least 0.8 over at least 20 candidates per hardware fixture, measured for real. ADR 0007 fixes the cost model shape (`c0 + f(M)`, c0 per graph mode, roofline as the prior), ADR 0025 the objective (limits, then quality, resource cost, speed; Pareto front), ADR 0027 the plan IR. What Phase 1 to 4 can execute on one box is a layer split, tensor-to-buffer overrides (experts on the CPU), threads, ubatch, ggml op offload, and in the own MoE builder expert slot counts per tier. Box time is the scarce resource, and the exit test must run offline in CI.

## Decision

- **Candidate.** A candidate is a complete `Plan` (ADR 0027) whose `knobs` carry the run settings. `plan::Knobs` gains three optional, additive fields: `threads`, `ubatch`, `op_offload` (absent means the engine default). A candidate is lowered to what runs it: llama-bench / `tetraeder bench` arguments for the libllama path (`-ngl`, one `-ot` regex per CPU expert layer range, `-t`, `-ub` with `-b` at least `-ub`, `-nopo 1` when op offload is off, `-fa 1`), or `exit_regime` environment for the builder path (slot bytes per tier, threads, ubatch, op offload).
- **Model layout.** Per-tensor bytes come from the GGUF (`xtask gguf-layout <file>` writes JSON: per layer the attention, dense FFN or router, and stacked expert bytes and types; embed and output). Memory checks and lowering use it; `ModelDesc` stays the unit-level view.
- **Enumeration is fixed before scoring.** `planner::enumerate(hw, layout, hints, phase)` is deterministic and uses only capacities, the model layout and hints, never the calibration. On one GPU plus CPU it takes placements (dense: layers on the GPU, from the largest that fits down in even steps; MoE: all dense weights on the GPU and the experts of layers `[k, L)` on the CPU, from the smallest `k` that fits upward) times knobs (threads in {quota, quota / 2}, ubatch in {512, 2048}, op offload on and off), drops what fails the memory check (weights plus KV plus a compute buffer estimate plus the measured reserve), and returns the grid capped at 32 by a fixed thinning rule. The measured candidate set of a fixture is exactly that output, written next to the results.
- **Cost model.** Per op and device `t = c0(mode) + max(FLOPs / F, bytes / B)` with F and B per device; the CPU's F and B are piecewise linear curves over threads. A decode token costs the ops and active weight bytes per device (experts at top-k over E), plus a hop of alpha plus activation bytes over beta per backend switch. A prefill ubatch costs the same with M tokens; with op offload and M at least 32 the CPU-resident matmul weights cross PCIe once per ubatch and compute on the GPU. A request of P prompt and N output tokens costs `t_pp(P) + N * t_tg`; that time for the fixture's workload hint is the score.
- **Calibration from anchor runs.** Per box and engine, a fixed anchor set (CPU only at several thread counts, all experts on the CPU with op offload on and off, the largest GPU placement) is measured in its own stage, never reusing candidate runs even when a config coincides. A fit in log space (deterministic coordinate search) sets F, B, c0 per graph mode, the thread curves and the PCIe beta, written back into the `HardwareGraph` as `Source::Measured` values. Residuals of the anchors are kept; the error band for "close call" comes from them.
- **Scoring the planner.** Per fixture: predicted and measured request time (median of repeats) per candidate. Regret = measured time of the planner's pick over the best measured time, minus 1. Rank correlation = Spearman over all candidates that ran. Candidates that failed on the box (out of memory) are listed and counted as a planner miss when it predicted them feasible. The planner's pick follows docs/plan.md "Search" step 5: if the top two are within the anchor error band, both are benchmarked and the faster wins; regret is reported for the analytic pick and for the final pick.
- **Baselines.** Same session, same threads: llama.cpp's own fit (`llama-bench -fitt`, the fitter behind `llama-fit-params`) and hand-tuned `-ot` configs (all experts on the CPU, and the largest expert layer range that fits). The planner's pick must be at least as fast on the score.
- **Hardware fixtures.** Real: an RTX 3090 box with part of its VRAM held by a balloon process (as `scripts/exit_run.sh` balloons RAM), so Qwen3-30B-A3B Q4_K_M and Qwen3-32B Q4_K_M overflow the GPU and placement matters; the fitter reads free memory, so it sees the same budget. Simulated: every fixture under `crates/costmodel/fixtures` and the calibrated 3090 box. Measured sets go to `bench/results/<date>/planner-*.json` and are read by CI tests.
- **Search beyond one box** (docs/plan.md steps 1 to 4) is implemented on the simulated fixtures: skeletons per device group, memory pruning, layer split by dynamic programming over uneven stages, experts placed greedily by routing frequency, analytic score, top 20 through the simulator.
- **Hints and objective** as ADR 0025: limits filter, then quality, then resource cost (`cost` per device), then speed; `tradeoff` picks a point on the speed and quality front; an infeasible request names the failing limit and returns the closest plan.
- **Quality** enters through a trait `QualityProfile` (loss per unit and format, `None` when unknown) with a null implementation that keeps source formats. Formats per unit come from a greedy knapsack over it (least loss per byte saved first). The file format of the profile is Track B's (quality profile ADR); an adapter implements the trait.
- **Explain, diff, what-if.** `explain` gives predicted time per stage and device, the binding resource, the runner-up and the term it lost on, formats and their loss, and the front. `diff` is `plan::diff` plus a switch time (bytes moved over tier bandwidth plus a reload). `what-if` adds or removes devices from a priors database (`crates/planner/priors.toml`, spec-sheet numbers per device class), scaled by the measured over spec ratio of a same-kind device on the box, and re-solves.
- **PCIe topology.** On Linux the profiler reads `/sys/bus/pci/devices`: the upstream bridge chain of each GPU and NVMe and link speed and width (current and max). Devices behind one non-root upstream port form a lane group with that port's bandwidth. Elsewhere it adds a note.
- **CLI.** `tetraeder plan candidates|explain|diff|what-if` over the planner library; `planner`, `analysis` and `control` do not depend on `ggml-sys`.

## Consequences

- The exit test needs one box session per measured set and then runs offline in CI from committed JSON.
- Calibration and candidates are separate stages, so the test cannot fit to its own answers.
- Rank correlation is only as good as the spread between candidates; the measured repeat spread is kept to show which adjacent ranks are distinguishable.
- The cost model is analytic for batch 1; the discrete-event simulator covers load and fault injection.
