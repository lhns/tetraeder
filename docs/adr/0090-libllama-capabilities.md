# 0090. libllama capabilities in `tetraeder serve` (parity group D)

Status: Accepted (owner, 2026-11-23, ADR 0083 group D). After M2. Matrix: [docs/notes/llamacpp-parity.md](../notes/llamacpp-parity.md). Tree node `serving-parity-libllama`.

## Context

ADR 0083 asks that a command line and a request that work against llama-server at the pin (b12426) work against `tetraeder serve` on the same GGUF, or are refused in llama-server's words or with a pointer to what works. Group D is what libllama can do and the gateway did not expose: KV offload, KV cache types, CPU-MoE tensor overrides, embeddings, reranking, context shift, slot save and restore, and model download by name. The own builders (`--engine dense`, `--engine moe`, and `auto` on `qwen3moe`) have their own KV pool and cannot honour most of them yet.

## Decision

1. **Honoured by libllama, refused by the own builders.** Every flag below reaches the libllama context. On a builder it is refused when `serve` starts (before the port opens), with a message that names `--engine llama` or the builder's own flag. Nothing is ignored. Refusals sit in `ServeArgs::check_libllama_flags` and `kv_choice`, after the engine is resolved (`auto` picks by architecture). `--plan` and `--worker`: the placement and context flags conflict with `--plan` (it sets its own placement); the flags that need the scheduler's backend (`--context-shift`) fail at start with the backend's reason when it is a worker process, which cannot shift.
2. **`--no-kv-offload` / `-nkvo`, `--kv-offload` / `-kvo`** set `offload_kqv` (ADR 0084 step 0). The last of the pair wins. Builders: refused, ADR 0084 step 1 plans host KV there.
3. **`--cache-type-k` / `-ctk`, `--cache-type-v` / `-ctv`** take llama-server's names (`f32 f16 bf16 f8_e4m3 q8_0 q4_0 q4_1 iq4_nl q5_0 q5_1`, exact, lower case) and set `type_k` and `type_v`; libllama refuses a type its kernels cannot run (quantized V needs flash attention). `LlamaBackend::kv_format` reports the real pair, which keys the prefix cache. On a builder the pair maps onto `--kv` when `--kv` allows it (`q8_0/q8_0`, `q8_0/q4_0`, ...); an unset side is `f16`; any other pair is refused with the allowed list. `--kv` and `-ctk`/`-ctv` together conflict.
4. **`--cpu-moe` / `-cmoe`, `--n-cpu-moe N` / `-ncmoe`** add the tensor overrides llama-server adds (`\.ffn_(up|down|gate|gate_up)_(ch|)exps` to CPU, per layer `blk\.N` + that regex for the first N), after the `--override-tensor` ones. The MoE builder is refused with a pointer to `--expert-slots`, `--ram-slots` and `--miss cpu`; the dense builder, which has no expert tensors, is refused too.
5. **Single-dash names.** clap has no multi-character short flags (`-hf` reads as `-h -f`). `main` rewrites llama-server's `-nkvo -kvo -ctk -ctv -cmoe -ncmoe -hf -hfr -hff` to their long forms before parsing, up to `--`. The other group D flags are long in llama-server too. This matches the repo's `--ngl` alias precedent. Environment variables (`LLAMA_ARG_CACHE_TYPE_K`, `..._CPU_MOE`, `..._EMBEDDINGS`, `..._RERANKING`, `..._POOLING`, `..._SLOT_SAVE_PATH`, `..._HF_REPO`) work for the flags that have a value.
6. **Embeddings and reranking** (`--embeddings`, `--reranking`, `--pooling none|mean|cls|last|rank`) run in a second libllama context on the model the scheduler already holds (`tetraeder_engine::Embedder`: `embeddings = true`, one input per decode, an output on every token). The generation context is untouched. Costs: a second compute buffer and a KV allocation of `--step-tokens` positions, and the two contexts share the CPU threads, so an embedding request slows decoding while it runs. Routes: `/embedding`, `/embeddings` (native: `[{index, embedding: [[...]]}]`), `/v1/embeddings` (OpenAI list object, `encoding_format` float or base64), `/rerank`, `/reranking`, `/v1/rerank`, `/v1/reranking` (Jina shape, TEI shape when the body has `texts`). Bodies, input shapes, `embd_normalize` (default 2, `common_embd_normalize`), the pooling `none` rule (native gives one vector per token, OpenAI is a 400) and the error texts follow `handle_embeddings_impl` and `handle_rerank_impl`. Without the flag the routes answer 501 `This server does not support embeddings. Start it with \`--embeddings\`` and `... reranking. Start it with \`--reranking\``. The rerank prompt is the model's `rerank` chat template, else `[BOS] query [EOS] [SEP] document [EOS]` as the vocabulary asks (`format_prompt_rerank`). An input beyond `--step-tokens` is a 500 with llama-server's `increase the physical batch size` text. Image and video items are 400. Refused with `--plan`, `--worker`, `--fake` and on the builders.
7. **`--context-shift` / `--no-context-shift`** (default off, as at the pin). A decoding sequence whose cache is one position from full (`fed + 1 >= n_ctx`) drops `n_discard` positions after `n_keep` and moves the rest down (`llama_memory_seq_rm` then `seq_add`), as `pre_decode` does: `n_keep` is the request's (`n_keep`, negative means the prompt; default 0) plus one when the vocabulary adds a BOS, at most `n_ctx - 4`; `n_discard` is the request's, else half of what is left, never all of it. A sequence that cannot shift anything ends with `length`. A shifted sequence is freed when it ends, never kept as an idle prefix or saved to the prefix cache (shifted K is not bit-equal to recomputed K, and its tokens are no prompt a client resends), and it is not drafted for under `--spec`. With the flag the gateway no longer clamps `max_tokens` to the room left in the context (an unset one is unbounded until the client stops, as `n_predict` -1 is there). The backend must report `can_shift` (a cache that can drop a middle range: not recurrent or hybrid models): else `serve` fails at start with that reason, where llama-server warns and turns the flag off. Builders and worker processes: refused.
8. **`--slot-save-path DIR`** turns on `POST /slots/{id}?action=save|restore|erase` (501 without it, `Invalid slot ID`, `Invalid action`, `Invalid filename` as there; `fs_validate_filename` is copied). Slot `i` is the scheduler's sequence `i` of `--parallel`, which is also what `id_slot: i` on a request selects (`SamplingExtras::slot`; a request waits while that sequence runs, an id out of range is a 400; without `id_slot` the scheduler picks as before). The ids are not sticky: an idle sequence is evicted to the prefix cache when its id is needed, so a client that wants a known slot sends `id_slot`. A save writes the idle sequence's tokens and KV snapshot (the scheduler's own `seq_snapshot`, so a file is not a llama.cpp state file) to `DIR/filename` and answers `{id_slot, filename, n_saved, n_written, timings.save_ms}`; a restore replaces the slot's content, makes it an idle prefix and answers `{id_slot, filename, n_restored, n_read, timings.restore_ms}`; an erase answers `{id_slot, n_erased}`. A save on a slot that holds nothing writes an empty file and `n_saved` 0. The KV format is in the file and a file of another type is refused. An action on a running slot waits for it (llama-server defers it too). `GET /slots` is not part of this change. Builders: refused (their snapshots exist for the prefix cache only).
9. **`-hf` / `--hf-repo`, `-hff` / `--hf-file`** are refused with `download the GGUF ... and pass it with -m`. A download client (TLS, redirects, the HF cache layout, resume) would be a new direct dependency; `reqwest` is in the lock file only through the OTLP exporter. `tetraeder` has no `models` subcommand; the pointer names `hf download`. Revisit if the owner wants downloads.
10. **Metrics (rule 6).** The new routes are counted by the existing counter `tetraeder.gateway.requests` (`http.route` is the matched template, so `/slots/{id_slot}` is one series; `http.response.status_code`), shown in the existing panel "Requests by route"; the 4xx and 5xx of the new routes are visible there per route. No duration histogram is added: it would need its own panel and alert, and the request log already holds per-request times. No new panel or alert rule is added.
11. **Conformance.** `tests/conformance/parity` gets three keys: `tetraeder_refuses TEXT` (tetraeder must exit before it listens with TEXT in its message; the baseline is not started), `setup` (requests sent first) and `ctx`, plus the `vectors` mode (numbers equal within a stated tolerance, 1e-3, far above float summation order noise and below a wrong pooling or token list) and the engine `llama-moe` (libllama on the MoE fixture). The tiny fixtures have pooling `none`, so the embedding value cases pass `--pooling mean` to both servers; they have no rank head, and libllama then scores with the first value of the pooled state (softmaxed for Qwen3), which both servers compute, so the rerank value cases compare those scores at 1e-5 and the unsupported path is a case of its own.

## Consequences

- A llama-server command line that uses these flags works on libllama, or fails at start with a message that says what to use. `--engine auto` on `qwen3moe` is the MoE builder, so `--cpu-moe` there needs `--engine llama` (the message says so).
- A second context doubles the compute buffer of an embedding server; an embedding-only deployment should not also serve generation.
- Open: `GET /slots` and `--slots`, model download by name, host KV on the builders (ADR 0084 step 1), GPU runs of rows 1 to 3 (CI has no GPU; the flags reach libllama's `offload_kqv`, `type_k`, `type_v` and tensor overrides as llama-server sets them).
