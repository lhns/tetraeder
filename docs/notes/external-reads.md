# External projects and papers read (not studies)

Short verdicts from a project's README or a paper's abstract, no code read or run. Their numbers are self-reported. A full read-only study, when one is worth it, gets its own file here (`surogate-study.md`, `inferssd-study.md`).

## 2026-11-19

- **Kinetic** (github.com/Veloresearch/kinetic, Apache-2.0, Rust, 0.1.0 beta, two days public). GGUF engine for CPU, CUDA and Vulkan with an OpenAI-compatible server, single GPU only (multi-GPU on its roadmap). Overlaps ours in two places: prompt-state reuse in RAM and on disk ("Warm Start", our prefix cache, ADR 0049, 0074) and MoE experts kept on the GPU with the rest memory-mapped from RAM, a missing expert run on the CPU or copied in, whichever is cheaper ("Flywheel", our Track B). Its speedups are on 1.7B to 4B models on a laptop RTX 3060, mostly on repeated prompts; plain generation is 1.0 to 1.2x llama.cpp and prefill level. Not a Phase 5 baseline. Candidate Track B study: how Flywheel chooses between computing a missing expert on the CPU and copying it (`docs/m2-plan.md`, Track B).
- **NanoQuant** (github.com/SamsungLabs/NanoQuant, Apache-2.0; ICML 2026, arXiv 2602.06694). Post-training weight quantization below 1 bit per weight (binary bases, ADMM), Python with its own CUDA kernels, no GGUF or llama.cpp path, no perplexity comparison with GPTQ, AWQ or GGUF quants in the README. Formats below 4 bits are parked to Phase 9; it would need kernels in the patch queue (rule 8), not justified before it shows quality against low-bit GGUF formats.
- **Blink** (arXiv 2604.07609, no code). Serving with the host CPU out of the steady-state path: a SmartNIC writes requests into GPU memory over RDMA and a persistent GPU kernel batches, schedules and manages the KV cache. Claims up to 8.5x lower p99 TTFT than vLLM, SGLang and TensorRT-LLM and stability under CPU interference. Needs hardware rented boxes do not have. The usable lesson, less host work per token, is the direction the executor already takes (CUDA graph replay, range uids and async input uploads, ADR 0069).
- **Speedy** (github.com/DevDock-AI/Speedy, a Strata fork). Runs the 125B MoE Qwen3.8-Flash-Next on one or two RTX 3080 10 GB cards with experts in system RAM: about 187 tok/s decode and about 4,200 tok/s prefill at 120K to 200K on two GPUs (layer split with pipelined decode windows), a conversation cache for follow-ups. Baseline is Strata, not llama.cpp; numbers use a third-party module that lifts the cards' FP16 tensor rate; quality checked on one IFBench run. Closest to Track B (expert streaming, long-context prefill); it belongs with the parked Strata pairing (`docs/m2-plan.md`, open items), nothing for Phase 5.

## 2026-11-20

- **QuixiInfer** (github.com/QuixiAI/QuixiInfer, MIT, Rust, no releases). Engine for one model, DeepSeek-V4.1-Flash at UD-IQ2_XXS with 262k context, on one RTX 5090 with an AVX-512 VNNI CPU. Its own CUDA kernels launched through CubeCL, no ggml at runtime (llama.cpp only as tokenizer and logits oracle); GGUF converted to its own pack. OpenAI-compatible server with continuous batching over sequence slots, prefix continuation, admission of the waiting request with the longest shared prefix first, and exact speculative decoding drafted from text already seen. Routed experts in three tiers (VRAM, pinned RAM, NVMe via io_uring), promoted by decayed routing frequency; a missing expert is copied in or run on the CPU. Single GPU only (multi-GPU listed as not done). Baseline is Strata, not llama.cpp: 16k prefill 11.7 s against 19.2 s, decode about 32.5 against 27.2 tok/s, Strata measured cold. Not a Phase 5 baseline. For Track B: a working decayed-frequency tier policy (our gfreq replay, ADR 0050) and the same copy-or-compute choice as Kinetic; for the scheduler, prefix-first admission (`docs/m2-plan.md`, TTFT).
- **Basalt** (github.com/jesdga95/basalt, MIT, C++ with CMake, a Strata fork with Infernix kernels; 1.5k stars, 3,115 commits, prebuilt Linux and Windows releases). Engine for Blackwell only (CC 12.0, CUDA 13), four models (Qwen3.8-Flash-Next, DeepSeek-V4.1-Flash, Qwen3.8-27B, Hy4-flash) in its own `.basalt` files, OpenAI and Anthropic APIs, up to 8 parallel slots, conversation checkpoints in RAM and on disk, speculative drafting on by default. Credits ggml and llama.cpp without saying how it uses them. The part closest to Phase 5 is its multi-GPU design (`docs/configuration/gpus.md`), chosen by a cost model fed by link rates probed at start, like our planner (ADR 0068): unlike cards get an expert tier (the main card runs every layer, peers hold and compute the experts it lacks, dealt out by bandwidth, hottest first; long prompts pipelined over layer blocks); matched cards get a layer split, where the first card starts the next decode window on a guess that the previous window's drafts are all accepted. Tensor parallel was priced and not built: host-staged exchanges (about 5.4 us per 10 KiB, no P2P or NCCL) cancel the saving. Reported: 5090 plus 5060 Ti expert tier 7.9 ms per window against 13.4 to 13.7 ms layer split; two 5080s 147 tok/s against 141 predicted. No llama.cpp comparison in the README; community numbers are on an external site. Not a Phase 5 baseline (Blackwell only, models we do not run). Worth a read before Phase 5 adds mixed GPU pairs: an expert tier is a split mode our candidate set lacks.

## 2026-11-21

- **StrataFlux** (arXiv 2611.08363, no code linked). Low-bit weights (2 to 4 bits) and KV (2 to 3 bits) in VRAM, with the missing precision streamed back from RAM or SSD only where it matters ("selective precision streaming"): transfers overlap compute and fetched refinement is reused across decode steps. Claims on an RTX 5090: Llama-3.1-8B at 2-bit weights, WikiText-2 perplexity 9.46 to 8.40 at 95.4% of the quantized throughput; Qwen3-8B at 2-bit weights and KV, AIME 11.0% to 47.1% at the same GPU memory; at 128K context, 3-bit weights with 2-bit KV match vLLM with AWQ 4-bit and 8-bit KV at about half the GPU memory. Not a Phase 5 baseline. It is our tier machinery (VRAM, RAM, NVMe, with prefetch and reuse) applied to precision instead of whole experts, so it fits two parked items: 1 to 2 bit formats as planner choices (feature 50, needs the importance-matrix path, ADR 0047) and Track B. Worth a read when either resumes; first question is what unit it refines (tensor rows, groups, residual planes) and whether that unit maps onto ggml quant blocks without a kernel change.
