# External projects and papers read (not studies)

Short verdicts from a project's README or a paper's abstract, no code read or run. Their numbers are self-reported. A full read-only study, when one is worth it, gets its own file here (`surogate-study.md`, `inferssd-study.md`).

## 2026-11-19

- **Kinetic** (github.com/Veloresearch/kinetic, Apache-2.0, Rust, 0.1.0 beta, two days public). GGUF engine for CPU, CUDA and Vulkan with an OpenAI-compatible server, single GPU only (multi-GPU on its roadmap). Overlaps ours in two places: prompt-state reuse in RAM and on disk ("Warm Start", our prefix cache, ADR 0049, 0074) and MoE experts kept on the GPU with the rest memory-mapped from RAM, a missing expert run on the CPU or copied in, whichever is cheaper ("Flywheel", our Track B). Its speedups are on 1.7B to 4B models on a laptop RTX 3060, mostly on repeated prompts; plain generation is 1.0 to 1.2x llama.cpp and prefill level. Not a Phase 5 baseline. Candidate Track B study: how Flywheel chooses between computing a missing expert on the CPU and copying it (`docs/m2-plan.md`, Track B).
- **NanoQuant** (github.com/SamsungLabs/NanoQuant, Apache-2.0; ICML 2026, arXiv 2602.06694). Post-training weight quantization below 1 bit per weight (binary bases, ADMM), Python with its own CUDA kernels, no GGUF or llama.cpp path, no perplexity comparison with GPTQ, AWQ or GGUF quants in the README. Formats below 4 bits are parked to Phase 9; it would need kernels in the patch queue (rule 8), not justified before it shows quality against low-bit GGUF formats.
- **Blink** (arXiv 2604.07609, no code). Serving with the host CPU out of the steady-state path: a SmartNIC writes requests into GPU memory over RDMA and a persistent GPU kernel batches, schedules and manages the KV cache. Claims up to 8.5x lower p99 TTFT than vLLM, SGLang and TensorRT-LLM and stability under CPU interference. Needs hardware rented boxes do not have. The usable lesson, less host work per token, is the direction the executor already takes (CUDA graph replay, range uids and async input uploads, ADR 0069).
- **Speedy** (github.com/DevDock-AI/Speedy, a Strata fork). Runs the 125B MoE Qwen3.8-Flash-Next on one or two RTX 3080 10 GB cards with experts in system RAM: about 187 tok/s decode and about 4,200 tok/s prefill at 120K to 200K on two GPUs (layer split with pipelined decode windows), a conversation cache for follow-ups. Baseline is Strata, not llama.cpp; numbers use a third-party module that lifts the cards' FP16 tensor rate; quality checked on one IFBench run. Closest to Track B (expert streaming, long-context prefill); it belongs with the parked Strata pairing (`docs/m2-plan.md`, open items), nothing for Phase 5.
