## Deviations and notes

- **Unverified code.** `cargo clippy`, `cargo test` and the Windows build were not run for `segment.rs`, the new subcommand and the `exit_regime.rs` change (no CI on this branch name, no local builds).
- **No tests for the new code.** `segment-predict` (`crates/planner/src/segment.rs`, `tetraeder-plan segment-predict`) and the session scripts were written for this session without CI (the branch name does not match `ci.yml`'s branch list and the local machine builds nothing); they compiled on the box (`build/main.log`) and ran end to end on the synthetic 8-layer MoE first (rehearsal, not committed). The fit-back test and the replay-against-engine counter test of ADR 0092 section 8 (node `planner-costmodel-v6-rest`) remain open; `segment-predict` should get them and fold into `predict --cluster`. The decode-window fields the host sampler needs (`decode_windows`, `hot_refresh_s`) were added to the segment run in `crates/model/tests/exit_regime.rs`.
- **Stage 2 slots.** My choice of 16 VRAM + 28 RAM slots per builder (ADR 0092 owner answer 4's single-node reference) failed the graph allocation on the 24 GB card (two chained builders each hold their dense weights, slots and compute buffers: `Ggml(Alloc { what: "graph tensors" })`, `trace/whole-model.log` of the first try was overwritten); stage 2 ran with 8 + 28. The trace records routing, which does not depend on the tiers, and the replay mirrors the segment's own tiers.
- **Host.** The brief asks for RAM for the whole model; only two 3090 offers with 100 GB or more were listed, hosts 546840 (never finished the image pull, `docs/box-driver.md`) and 166946 (rejected the key on 2026-11-17), so host 88910 (an RTX 3090 offer with 252 GB listed, `memory.max` 519 GB; what was relaxed is `--min-inet 1000` to 500, the link is between 800 and 1000 Mbit/s, the download ran at about 100 MB/s) was taken, its disk at 6.3 GB/s is above the 5 GB/s of the machine rules; the segment needs only 59 GB of RAM under the balloon. The balloon is 455 GB (it took 4 minutes to fill). The co-tenant sample at SSH read 22.5 to 23.3 outside cores (limit 19.2) and 15.6 after the build began; runs went ahead because the gate of record is the per-run `cotenant_ok`, which held on every run (the host was this busy all session: 3 to 17 outside cores in the decode windows).
- **Thread count** 61 (the cgroup quota floor) in every run, anchors and judged alike; unpinned.
- **Sources of numbers.** Every rate comes from `runs[0].prefill_tok_s` and `runs[0].decode_tok_s` of the round JSON (`judged/r*.json`, `report/*.json`, `anchors/*.json`), the routing gate from `decode_layers` and `predictions/pred.json`; `verdict.json` is `scripts/sc_summary.py` over them. Not fetched or committed: the routing trace, the hidden rows, the 1 Hz sampler files (`*.samples.jsonl.gz`), `report/fitted-real-anchors.toml`.
- **Not measured as a ratio.** This session measures a prediction error, not a paired ratio, so `docs/features.md` has no row to move.
