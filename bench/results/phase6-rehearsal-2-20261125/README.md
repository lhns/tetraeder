## Defects and open items

1. Clock offset by taxameter ssh has an uncertainty of 2.3 to 6.3 s against the 0.5 s rule, so `clock_offset` fails and a fault can land off its window (daemon trial 2). Node `bench-phase6-clock-offset`.
2. `phase6_box.sh serve` lacks `--node-state $P6/node-state`: the head's in-process replica cannot serve prefix fetches (the daemon closes the connection). Node `bench-phase6-serve-node-state` (script fix).
3. A prefix fetch was not observed with the flag fixed; no grant log line, no readable counter. Node `cluster-prefix-fetch-not-observed`.
4. A plan whose leader is the head runs the whole model in process and ignores the plan's other segments, silently (c00: node b idle, tg 190 tok/s). Node `cluster-head-led-plan-ignores-segments`.
5. After one cold request the next cold request through the plan path returned an empty 200 stream (runs 2 to 4); no error in the logs read. Node `cluster-second-cold-request-empty`.
6. `cluster probe` with 64 MiB frames and 10 repeats dies on the daemon's 30 s control-idle limit when a frame takes long (a to b here, bulk 2 to 15 s per 4 to 32 MiB); the probe cannot run to 64 MiB on a link like this one. Node `cluster-probe-control-idle`.
7. The Case F script ran `cert` before the build on a fresh box (fixed on the branch).
8. The 30B judged prediction is not possible without a routing trace and the `exit_regime` build; `phase6_exit_s.sh` is 235B-only (fetch, layout path, `disk_gb`), so the Case S machinery was not exercised for the 30B beyond the planner, probe and merge steps.
