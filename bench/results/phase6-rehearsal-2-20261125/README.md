### Second cold request, most likely cause

Read from `split30/` (the committed admit lines and round files; the replica's own log at warn level was not kept). Every failed round shows one of two shapes. Run 3 r2: admitted at 14:02:38.0 after `place_ms=5211.60 save_ms=5045.66 attempts=2 saved=2:2177` (the eviction of r1's 2177-token idle sequence, saved through the remote segment over the WAN), ended 1.3 s later with `completion_tokens 0, cached_tokens 1`. Run 3 r3 and run 2 r1 to r3: no usage event, ended 5.4 to 5.6 s after submit (run 3 r3, run 2 r1), or sooner (run 2 r2 1.35 s, r3 0.15 s). Two facts point at one cause. The save took 5.05 s, the `RemoteConfig::deadline_floor` of every call is 5 s (`max(5 s, 10 x predicted decode step)`, and the prefill step and the snapshot got the same deadline as a decode step), and the a to b bulk path varied from 0.9 to 2.8 s per 4 MiB. A call past the deadline kills the segment worker (`recv_call`), the backend then reports its sequences lost and fails the request. The failure is an error event on an open 200 stream, and `scripts/phase6_split_round.py` reads only `usage` and `choices` from the stream, so an error event shows as an empty stream with `error: null`. The CPU test passes because its snapshots and steps take milliseconds, and run 1's repeated prompt never evicted (it hit the idle sequence, `common=2047`).

Not proven (no replica log). Fix made: `RemoteConfig::bulk_deadline` (120 s) for `seq_snapshot`, `seq_restore` and prefill steps (more than 64 tokens); a dead node is the heartbeats' job, not the reply deadline's. Tests `a_snapshot_over_a_slow_link_is_not_cut_at_the_floor` and `a_slow_prefill_step_gets_the_bulk_deadline_a_slow_decode_step_does_not` (a worker with `slowsnap:2000` and `slow:60` faults against a 1 s floor). A box run settles it with: the replica child's stderr at warn level (`node.log` of the leader), these two lines and `cannot save a sequence`, and `phase6_split_round.py` recording an `error` event of the stream (CI lane's script, read only here).
